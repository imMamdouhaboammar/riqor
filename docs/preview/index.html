Three controls around the work

Riqor stays close to the local workflow. It does not change the model or attach to unrelated sessions

01

Evidence gate

Successful workspace mutations keep verification pending until a relevant check completes successfully

02

Session activator

At a safe Codex lifecycle point, Riqor reviews the goal, progress, evidence, and scope before work continues

03

Clean rollback

Versioned payloads and managed shell files can be removed through one documented uninstall path

Explicit local boundaries

The security model documents what Riqor reads, stores, launches, ignores, and removes

What stays local

  • ✓Verification state and lifecycle timing
  • ✓Versioned package payloads and command shims
  • ✓Managed Codex child process scope
  • ✓Bounded activator records with hashed filenames

What Riqor does not do

  • ✓No model weight modification
  • ✓No attachment to unrelated Codex sessions
  • ✓No network listener or activator daemon
  • ✓No prompt, transcript, command, or source retention in activator state
