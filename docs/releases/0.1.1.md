# Riqor v0.1.1

Released: 2026-08-08

`0.1.1` is a production hardening release for the npm distribution and local installation lifecycle.

## Package and installer fixes

- Bundles the shell and Codex plugin lifecycle scripts required by the published npm runtime
- Runs package-mode shell and plugin installation without requiring Bun on the user's machine
- Installs the bundled Codex plugin automatically when Codex CLI is available
- Defers plugin setup with an explicit diagnostic when Codex CLI is not installed yet
- Creates `CODEX_HOME` before plugin registration when a custom or clean home is used
- Keeps XDG configuration paths consistent between the installer, `.zshenv`, and Kaku integration
- Migrates the legacy `0.1.0` managed shim without treating it as an unrelated file

## Safety fixes

- Refuses to overwrite unrelated `riqor`, `codex-harness`, or `cxh` executables
- Preserves unrelated executable paths during uninstall and reports incomplete cleanup
- Removes only Riqor-owned version directories instead of deleting arbitrary files below the data root
- Fails closed when managed shell markers are malformed, leaving the existing `.zshenv` unchanged
- Excludes `.DS_Store`, `Thumbs.db`, and AppleDouble `._*` files from packaged payloads and plugin archives
## Diagnostics and verification

- `riqor doctor --package-only` now hashes every runtime file against `provenance.json` and rejects missing, modified, unexpected, or path-traversing entries
- Codex doctor core health is evaluated independently from unrelated installation/update warnings
- `riqor status` reports `missing` when package metadata is unavailable instead of using hard-coded version fallbacks
- Install success now includes shell, plugin when applicable, manifest, and package integrity checks instead of ignoring failed post-install diagnostics

## Upgrade

```bash
npx riqor@0.1.1 install
riqor version --json
riqor doctor --json
```

The installer recognizes the managed wrapper signature produced by the affected `0.1.0` path and replaces it with the `0.1.1` shim. It still refuses unknown executable contents.

Homebrew remains an independently published channel. The repository formula keeps pointing to the last verified Homebrew artifact until a matching Homebrew release is published.
